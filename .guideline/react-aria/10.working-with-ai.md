# React Aria active baseline

This file documents the React Aria baseline that is actually active in `afenda-next`.

## Framework setup

- Runtime: `Next.js App Router`
- Locale source: `Accept-Language` request header in `src/app/layout.tsx`
- Document attributes: `<html lang>` and `<html dir>` are set server-side
- Client locale provider: `ClientI18nProvider` (React Aria `I18nProvider`) in `src/client-runtime/client-runtime.i18n.provider.client.tsx`

## Global AI and MCP setup

- Global React Aria MCP dependency: `react-aria` server configured in `~/.codex/config.toml`
- Repo guideline source: `.guideline/react-aria/9.working-with-ai.md`
- Local contract sources: shared controls under `src/components/ui-governance/app-*` (`app-*.control.primitive.client.tsx` + approval manifests), and Interface Studio routes under `src/app/(app)/(public)/interface-studio` (registry in `interface-studio.config.ts`).

## Active repo contract

- Shared React Aria wrappers live in per-export folders: `src/components/ui-governance/app-*/app-*.control.primitive.client.tsx` (see `src/components/ui-governance/README.md`)
- Approved states and patterns are represented in `/interface-studio` (and enforced in CI via `pnpm check:workbench-contract` where applicable)
- Workbench contract enforcement runs from `scripts/repo.workbench-contract.check.automation.mjs`
- Semantic tests run with `Vitest`, `React Testing Library`, `user-event`, and `@react-aria/test-utils`

## Intentionally not configured

- `React Router` integration
- `SSRProvider`
- `PortalProvider`
- CSP nonce integration
- Locale routing or `next-intl`

These remain out of scope until the app has a concrete need for them.
